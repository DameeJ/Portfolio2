Global Layoffs: Data Cleaning & Exploratory Analysis

Taking a raw, inconsistent dataset of global company layoffs and turning it into a clean, analysis-ready table — then digging into it to find which companies and locations were hit hardest.

Overview

About this dataset

This project uses a global layoffs dataset sourced from Alex The Analyst, tracking company workforce reductions through 2023 in the wake of the COVID-19 economic slowdown. The raw data needed significant cleanup before it could be reliably analyzed — duplicate entries, inconsistent text formatting, and missing values all had to be addressed first.

Part One

Data Cleaning

Before any analysis could happen, the raw dataset needed to be standardized and trimmed down to what was actually usable.

Step 01

Remove duplicate records

Used a ROW_NUMBER window function partitioned across all key columns to flag duplicate rows, then removed any where the row number was greater than 1.

SQL — Identify duplicates
SELECT *
FROM (
    SELECT company, location, industry,
           total_laid_off, percentage_laid_off, `date`,
           stage, country, funds_raised_millions,
           ROW_NUMBER() OVER (
               PARTITION BY company, location, industry,
                            total_laid_off, percentage_laid_off,
                            `date`, stage, country, funds_raised_millions
           ) AS row_num
    FROM world_layoffs.layoffs_staging
) duplicates
WHERE row_num > 1;
Step 02

Standardize data & fix errors

Blank industry values were converted to NULL for easier handling. Inconsistent variations of "Crypto" across the industry field were unified into a single standard label.

SQL — Blank to NULL
UPDATE world_layoffs.layoffs_staging2
SET industry = NULL
WHERE industry = '';
SQL — Standardize Crypto variations
SELECT DISTINCT industry
FROM world_layoffs.layoffs_staging2
ORDER BY industry;

UPDATE layoffs_staging2
SET industry = 'Crypto'
WHERE industry IN ('Crypto Currency', 'CryptoCurrency');
Step 03

Review null values

Checked for rows where both key numeric columns were NULL. Decided to leave valid NULLs in place — they make calculations in the EDA phase cleaner than blank strings would.

SQL — Check for null rows
SELECT *
FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL;
NULLs in total_laid_off, percentage_laid_off, and funds_raised_millions were left intentionally — they represent genuinely missing data and are easier to handle in aggregations than empty strings.
Step 04

Remove unnecessary columns & rows

Rows where both total_laid_off and percentage_laid_off were NULL had no analytical value and were deleted from the staging table.

SQL — Identify rows to remove
SELECT *
FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL;
SQL — Delete useless rows
DELETE FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL;
Part Two

Exploratory Data Analysis

With a clean dataset in hand, the next step was digging in to understand the actual scale and shape of the layoffs.

Question 01

How big were the layoffs, relative to company size?

Calculated the max and min percentage laid off to understand the range — from small cuts to full shutdowns.

SQL
SELECT MAX(percentage_laid_off), MIN(percentage_laid_off)
FROM world_layoffs.layoffs_staging2
WHERE percentage_laid_off IS NOT NULL;
Finding
Some companies returned a percentage_laid_off of 1 — meaning they laid off 100% of their workforce and went under entirely.
Question 02

Which companies shut down entirely?

Filtered for companies with 100% layoffs, then ordered by funds raised to see how well-funded some of these failures were.

SQL
SELECT *
FROM world_layoffs.layoffs_staging2
WHERE percentage_laid_off = 1
ORDER BY funds_raised_millions DESC;
Finding
BritishVolt (an EV company) $2 billion in funding before shutting down completely. Followed by Quibi. A stark reminder that capital raised doesn't guarantee survival.
Question 03

Which company had the single biggest layoff in one day?

Sorted by total_laid_off descending to find the largest single-event workforce reduction.

SQL
SELECT company, total_laid_off
FROM world_layoffs.layoffs_staging
ORDER BY total_laid_off DESC
LIMIT 5;
Finding
Google, laying off 12,000 in a single day
Question 04

Which company and location had the highest total layoffs?

Aggregated total layoffs by company and separately by location to find where the biggest cumulative damage occurred.

SQL — By company
SELECT company, SUM(total_laid_off) AS total
FROM world_layoffs.layoffs_staging2
GROUP BY company
ORDER BY total DESC
LIMIT 10;
SQL — By location
SELECT location, SUM(total_laid_off) AS total
FROM world_layoffs.layoffs_staging2
GROUP BY location
ORDER BY total DESC
LIMIT 10;
Result — Top companies by total layoffs
1. Amazon — 18,150    2. Google — 12,000    3. Meta — 11,000
Result — Top location by total layoffs
The United States recorded the highest total layoffs of 256,559 across all locations in the dataset.
