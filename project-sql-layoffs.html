Overview

About this dataset

This project uses a global layoffs dataset covering company workforce reductions, believed to be sourced from [ Alex The Analyst], tracking layoffs through 2023 in the wake of the COVID-19 economic slowdown. The raw data needed significant cleanup before it could be reliably analyzed — duplicate entries, inconsistent text formatting, and missing values all had to be addressed first.

Part One

Data Cleaning

Before any analysis could happen, the raw dataset needed to be standardized and trimmed down to what was actually usable.

Step 01

Remove duplicate records

Identified and removed duplicate layoff entries to make sure each event was only counted once.

SQL
-- [ SELECT *
FROM (
	SELECT company, location, industry, total_laid_off,percentage_laid_off,`date`, stage, country, funds_raised_millions,
		ROW_NUMBER() OVER (
			PARTITION BY company, location, industry, total_laid_off,percentage_laid_off,`date`, stage, country, funds_raised_millions
			) AS row_num
	FROM 
		world_layoffs.layoffs_staging
) duplicates
WHERE 
	row_num > 1;]
Step 02

Standardize data & fix errors

Cleaned up inconsistent text formatting and corrected errors across fields like company name, industry, and location.

SQL
-- [ -- we should set the blanks to nulls since those are typically easier to work with
UPDATE world_layoffs.layoffs_staging2
SET industry = NULL
WHERE industry = '';
          -- I also noticed the Crypto has multiple different variations. We need to standardize that - let's say all to Crypto
SELECT DISTINCT industry
FROM world_layoffs.layoffs_staging2
ORDER BY industry;

UPDATE layoffs_staging2
SET industry = 'Crypto'
WHERE industry IN ('Crypto Currency', 'CryptoCurrency');]
Step 03

Review null values

Reviewed missing values across the dataset to decide what could be reasonably filled in, left blank, or flagged.

SQL
-- [ SELECT *
FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL;
          -- the null values in total_laid_off, percentage_laid_off, and funds_raised_millions all look normal.
          -- I like having them null because it makes it easier for calculations during the EDA phase]
Step 04

Remove unnecessary columns & rows

Trimmed the dataset down using a few different conditions to drop columns and rows that weren't useful for analysis.

SQL
-- [ SELECT *
FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL;

-- Delete Useless data we can't really use
DELETE FROM world_layoffs.layoffs_staging2
WHERE total_laid_off IS NULL
AND percentage_laid_off IS NULL; ]
Part Two

Exploratory Data Analysis

With a clean dataset in hand, the next step was digging in to understand the actual scale and shape of the layoffs.

Question 01

How big were the layoffs, relative to company size?

Calculated what percentage of each company's workforce was laid off, to gauge the real scale of the cuts beyond raw headcounts.

SQL
-- [ -- Looking at Percentage to see how big these layoffs were
SELECT MAX(percentage_laid_off),  MIN(percentage_laid_off)
FROM world_layoffs.layoffs_staging2
WHERE  percentage_laid_off IS NOT NULL;
			]
Result
[ Some companies are 1, meaning they totally went under ]
Question 02

Which companies shut down entirely?

Identified companies that laid off 100% of their staff — i.e., went under completely.

SQL
-- [ -- if we order by funcs_raised_millions we can see how big some of these companies were
SELECT *
FROM world_layoffs.layoffs_staging2
WHERE  percentage_laid_off = 1
ORDER BY funds_raised_millions DESC; ]
Result
[ BritishVolt looks like an EV company, Quibi! - wow raised like 2 billion dollars and went under - ouch ]
Question 03

Which company had the single biggest layoff in one day?

Found the largest single-day layoff event in the dataset.

SQL
-- [ SELECT company, total_laid_off
FROM world_layoffs.layoffs_staging

Question 04

Which company and location had the highest total layoffs?

Found the company with the highest cumulative layoffs overall, and separately, the location (city/country) with the highest total layoffs.

SQL
-- [ SELECT company, SUM(total_laid_off)
FROM world_layoffs.layoffs_staging2
GROUP BY company
ORDER BY 2 DESC
LIMIT 10;
			-- by location
SELECT location, SUM(total_laid_off)
FROM world_layoffs.layoffs_staging2
GROUP BY location
ORDER BY 2 DESC
LIMIT 10;]
